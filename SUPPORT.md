# Support

Use [GitHub Issues](https://github.com/dappnutchanon/RelayForge/issues) to report a bug, request a feature, or ask a question. Search existing issues first so related reports stay together.

For a report that contains private information, email [dappnutchanon@gmail.com](mailto:dappnutchanon@gmail.com). Send suspected vulnerabilities by email as described in [Security reporting](SECURITY.md).

## Reporting a bug

Include the app version and build, your Windows version, and the steps that led to the problem. Explain what you expected and what happened. Add the error code and approximate time if available. Screenshots help with layout problems; remove personal information before sharing them.

For a command or connection failure, say which type of command or server was involved and whether it started. A timeout alone does not show whether a command stopped or an external service completed a request.

## Sharing a support report

Open **Support report** in Settings. Review the preview, then choose **Copy report** and paste it into your issue or email.

The report includes the app build, platform, runtime health, and a limited set of recent error summaries. It excludes workspace paths, file contents, command arguments, environment variables, and raw crash dumps. A partial report can still be useful when the runtime is unavailable.

Review anything else you attach separately. Raw logs, command output, screenshots, and crash dumps may contain private information. Keep passwords, access tokens, tunnel credentials, and your full application data directory out of public issues. If you accidentally share a credential, revoke or rotate it.

## If the app will not open

Report the approximate failure time, app build if known, and the last action you took. Mention whether it followed an update. Preserve the application data and updater records for diagnosis; deleting the database can remove evidence and Task history.
